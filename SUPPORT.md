# mcp-sync support

`mcp-sync` uses public GitHub Issues for defects, proposed changes, and usage
obstacles. Support is provided on a best-effort basis; there is no guaranteed
response time or private product-support channel.

## Get help or report a problem

Before opening an issue:

1. Read the [usage and recovery guide](docs/m1-usage-and-recovery.md).
2. Search [existing issues](https://github.com/EnjoyableWork/mcp-sync/issues).
3. Use the [bug form](https://github.com/EnjoyableWork/mcp-sync/issues/new?template=01-bug-report.yml)
   for a reproducible defect, or the
   [feature and usage-obstacle form](https://github.com/EnjoyableWork/mcp-sync/issues/new?template=02-feature-request.yml)
   for a proposed improvement.

Only the latest public release receives security fixes. `main` and other source
snapshots are development versions. Questions about behavior owned by Claude
Desktop, Cursor, Windsurf, VS Code, Codex, a package manager, or another
third-party service should normally go to that project's support channel unless
the problem is caused by `mcp-sync`'s documented behavior.

Use generic server names and synthetic, redacted values. Never post credentials,
tokens, headers, environment values, private paths, user data, complete
configuration, or raw unreviewed logs. The complete reporting and contribution
workflow is in [CONTRIBUTING.md](CONTRIBUTING.md).

## Security and conduct concerns

Do not open a public support issue for a suspected vulnerability. Follow
[SECURITY.md](SECURITY.md) and use
[GitHub private vulnerability reporting](https://github.com/EnjoyableWork/mcp-sync/security/advisories/new).

For a conduct concern, follow the [Code of Conduct](CODE_OF_CONDUCT.md) and use
its detail-free public contact request to arrange private follow-up. Do not post
incident details or identities in the public request.
