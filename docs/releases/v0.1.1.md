# mcp-sync v0.1.1

`mcp-sync` 0.1.1 is the first repeat release of the local configuration CLI.
It keeps the canonical configuration at version 1 while strengthening safe
reconciliation, process cleanup, and release reproducibility across supported
macOS, GNU/Linux, and Windows hosts.

## Included

- Kiro is the sixth global configuration target. The adapter preserves
  comments and unowned data in Kiro's selected global-user configuration, and
  controlled macOS evidence verifies inheritance by Kiro Crew without managing
  a second Crew-specific file.
- Every mutating command is serialized per canonical configuration root, while
  read-only and dry-run commands remain lock-free.
- Existing-file replacement is target-first and journaled so an interrupted
  write can be classified and recovered before the next locked operation.
- `test <name>` contains, terminates, and reaps the complete process tree on
  supported hosts while retaining the five-second initialize-response limit,
  1-MiB response bound, 500-millisecond graceful-shutdown allowance, and
  structural redaction.
- Canonical environment names now fail validation before mutation or process
  start when they are empty or contain NUL or `=` and therefore cannot retain
  one portable identity.
- Windows ARM64 health fixtures use explicit readiness rather than interpreter
  startup timing, and release SBOM generation acquires one pinned Syft version
  through repository-owned, checksum-verified scripts.
- The protected repeat-release path is GitHub-first, publishes Cargo only
  through crates.io Trusted Publishing, updates Homebrew monotonically, and
  verifies every represented installed channel without reusable publication
  credentials.

## Install or upgrade

`mcp-sync` does not update itself. Updates are explicit and remain under the
user's control through the installation channel they selected.

Homebrew users on macOS and GNU/Linux can refresh the tap metadata and rebuild
the newer formula from its immutable Cargo source package:

```bash
brew update
brew upgrade --build-from-source EnjoyableWork/tap/mcp-sync
```

Cargo users on every supported platform can install the exact newer source
package. Cargo replaces a tracked older installation when the requested
version differs:

```bash
cargo install enjoyable-mcp-sync --version '=0.1.1' --locked
```

GNU/Linux ARM64 and x64 archive users should download `SHA256SUMS` plus the
archive matching their host from the `v0.1.1` GitHub Release. For example, on
x64 GNU/Linux:

```bash
gh release download v0.1.1 \
  --repo EnjoyableWork/mcp-sync \
  --pattern SHA256SUMS \
  --pattern 'mcp-sync-v0.1.1-x86_64-unknown-linux-gnu.tar.gz'
grep 'mcp-sync-v0.1.1-x86_64-unknown-linux-gnu.tar.gz$' SHA256SUMS \
  | sha256sum --check -
gh attestation verify \
  ./mcp-sync-v0.1.1-x86_64-unknown-linux-gnu.tar.gz \
  --repo EnjoyableWork/mcp-sync \
  --signer-workflow EnjoyableWork/mcp-sync/.github/workflows/source-linux-release.yml \
  --source-ref refs/tags/v0.1.1
tar -xzf mcp-sync-v0.1.1-x86_64-unknown-linux-gnu.tar.gz
./mcp-sync --version
```

After verification, replace the previous executable in the installation
location the user chose. The ARM64 archive uses
`aarch64-unknown-linux-gnu` in place of `x86_64-unknown-linux-gnu`.

Installing or replacing the executable does not read or modify canonical or
native client configuration. Configuration changes occur only when a user
later invokes a mutating `mcp-sync` command.

## Release integrity

The immutable GitHub Release contains exactly two native GNU/Linux archives,
their target-specific SPDX 2.3 JSON SBOMs, the Cargo source package, the
source-building Homebrew formula, and one SHA-256 manifest. Every uploaded file
has explicit GitHub build-provenance attestation, and the immutable release has
GitHub's release attestation.

Verify the release itself with GitHub CLI:

```bash
gh release verify v0.1.1 --repo EnjoyableWork/mcp-sync
```

The exact same Cargo package bytes are published as `enjoyable-mcp-sync`
`0.1.1` through tokenless Trusted Publishing and referenced by the Homebrew
formula. No project-issued macOS or Windows binary is included, and `v0.1.1`
is not published to WinGet. Those binary channels remain behind the funded
Apple and Windows signing pipeline; this release does not substitute unsigned
binaries.

## Scope boundaries

This release manages global configuration only. It does not discover or mutate
project-level Cursor, VS Code, or Codex files, named or remote VS Code profiles,
VS Code Insiders or extension-owned MCP stores, Codex credential stores,
Windsurf's Devin Local configuration, or excluded Kiro workspace, agent, Crew,
generated-agent, organization-managed, remote-service, or credential stores.
Remote and otherwise unrepresentable native entries are preserved and
collision-protected rather than converted or deleted.

Controlled current-client smoke evidence exists for Claude Desktop, Cursor,
Kiro IDE, and inherited Kiro Crew behavior on macOS. Fixture-backed and native
built-binary coverage proves all six implemented configuration targets across
supported macOS, GNU/Linux, and Windows hosts without claiming current-client
smokes for GNU/Linux or Windows, or for Windsurf, VS Code, or Codex on any
platform.
